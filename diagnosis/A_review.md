## A-2. 自己批判

### 禁じ手に逃げ込んでいないか

**1件、逃げ込んでいた。** H1 の対処として既に入っている `with_retry()` は、
禁じ手リストの「リトライ」そのものである。

弁明と区別: `wait_for_network()`（起動直後に接続を待つ）は**原因の除去**である
（原因＝接続完了前に取得を開始したこと）。一方 `with_retry()` は**症状を隠す**側に立つ。
両者が同じコミットに同居しているため、「原因を直した」という説明が
リトライの追加を正当化する隠れ蓑になっている。

今回はこれを触らない（H1 は対象外）が、**この構図は記録しておく必要がある**。
次に同種の失敗が起きたとき「リトライを増やす」で解決しようとする誘因になる。

### 「新規発見5件以上」は本当に新規か

**検証できなかった。** 元の診断指示書（H1〜H8 の仮説リストと禁じ手リストを含むはずのもの）
は前セッションの会話に埋もれており、ログからも Downloads からも回収できなかった。

したがって本書の8件が「与えられた仮説の言い換え」なのか「独立の発見」なのかを、
**私は判定できない立場にある**。これは査読としての欠落であり、取り繕わずに記す。
現実的な保証は「8件すべてがコードまたはログの実物に紐づいている」ことまで。

### 症状を原因として書いた箇所はないか

**ある。H2 と H3 は症状である。**

「総資産が94%過少」も「損益率の分母が混ざる」も、それ自体は出力の異常であって原因ではない。
両者の原因は同一で、A-3 に書く。診断書で H2/H3 を独立の所見として並べたのは、
**証拠として強い（数字で示せる）ことと、原因であることを混同**している。

H5 も同様に症状寄りだが、こちらは原因が別（新機能の実装順序の誤り）なので独立に扱う。

### 最も自信のない所見はどれか

**H7。** コード上の事実（`independent` がほぼ常に空）は確実だが、
そこから引いた「だから照合は永久に改善しない」は、**私が代替手段を探した形跡がない**まま
書かれている。無人で独立な残高ソースを得る手段（口座の日次メール、CSV の自動配信、
第三者アグリゲータ）を検討した記録がない。**調べていないことを「不能」と書いた。**

次に自信がないのは **H8 の「対話セッションで手作り」**。ログに記録が無いことは
「その経路で生成されていない」証拠にはなるが、「人が手で書いた」証拠ではない。
別の自動経路で生成された可能性を潰していない。

## A-3. 単一の根本原因

> **観測の試行が第一級のデータになっていない。**
>
> 取得結果を「値 または `None`」で表しているため、
> ①取得を試みて失敗した ②取得できて値が存在しなかった ③そもそも観測対象でなかった
> の3つが同じ `None` に潰れる。結果として**失敗は情報ではなく穴になり、
> 穴は下流で「無かったこと」として扱われ、穴のまま集計に入る。**

### なぜこれが最上流か

修理対象4件のうち **4件すべてがこれに従属する**。

| 所見 | 従属の内実 |
|---|---|
| H2 | `value_jpy is not None` で除外＝「失敗」を「存在しない」として扱った直接の帰結 |
| H3 | 分子と分母で `None` の意味が違う（片方は取得失敗、片方は算出不能）のに、同じ `is not None` で濾した |
| H4 | 節の失敗を「本文に無いもの」＝ `None` 相当として扱い、欠落として記録しなかった |
| H5 | 「品質不足」という**観測結果**を、state（データ）に残さず制御フロー（return）だけで表現した。試行の記録が残らないので再開できない |

H5 は一見すると別種（実装順序の誤り）だが、**「試行の結果を残さないまま制御を返す」**
という同じ形をしている。`save_state` の前に return するのは、
観測が第一級でないという設計の、制御フローにおける現れである。

### これを直すと自動的に消えるもの

- **H2 / H3**: 集計が「母数」と「観測できた数」を分離して持てば、
  過少表示も混合分母も**表示の段階で機械的に検出できる**（値を出す前に不一致が分かる）
- **H4**: 節の状態が `done / failed / skipped` として本文組立に伝われば、無言削除が起きない
- **H5**: 品質判定の結果を state に書いてから制御を返せば、再開タスクが拾える

### これを直しても消えないもの

- **H1**（起床レース）— ネットワークの時間的競合。データ表現とは無関係
- **H6**（再試行予算の単位）— 予算設計の問題
- **H7**（照合の循環）— 情報源の可用性の問題
- **H8**（本番未検証）— 検証プロセスの欠如

**H1 は対処済み、H6/H7/H8 は BACKLOG。** 今回の修理でこれらが消えることを期待しない。
