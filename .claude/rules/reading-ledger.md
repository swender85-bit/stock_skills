# 読書台帳・概念層・偏食監査（読書台帳仕様 v2）

## なぜあるか

> Stock Skills は自分の出力の記憶しか持っていない。持ち主が何を読んだかを記録すると、
> テーゼの根が地面に届き、知識が銘柄の死を超えて生き残り、自分の偏りが数値になる。

2026-08-08 の実測: 10ポジション中 thesis は2件、反証条件は1件、
実際に点検できたのは0件、根拠の記録は0件。
**データ取得層をいくら直しても、この4つの数字は1つも動かない。**

そしてこの層は **外部API依存がゼロ**である。価格が全滅した週に、
唯一無傷で価値を出せる層がこれ。冗長化ではなく**依存構造の分散**。

## 保有の記述状態（V0）— 「孤児0件」は誤報だった

| 状態 | 定義 | 意味 |
|---|---|---|
| **健全** | thesis + 政策 + 反証条件 | なぜ持つか・どうするか・何で否定されるかが揃う |
| **無方針保有** | thesis あり / 政策なし | 理由はあるが行動が未定義 |
| **根拠なき執行** | 政策あり / thesis なし | ルールはあるが理由がない |
| **完全孤児** | どちらもなし | どちらも未定義 |

旧実装は `orphan = NOT(thesis OR policy)` という **AND条件**で、
政策だけがある3xスリーブ・FANG+ を非孤児として通していた。その結果
「孤児0件・全銘柄に理由の記述あり」と書きながら、同じレポートの別の節に
「thesis は2件しか存在しない」と書いていた。

🔴 **表示すべき数字は「孤児0件」ではなく「健全0件」。**
そして **「根拠なき執行」は孤児より危険**である。孤児は「判断基準が無い」と
自覚できるが、政策があると「管理されている」という錯覚が生じる。

実装: `src/core/portfolio/description_state.py` → `reconciliation.description`

## 取り込み（V2）

```bash
python scripts/ingest_reading.py --status                      # 状態
python scripts/ingest_reading.py --title "..." --url ... --stdin  # 取り込み
python scripts/ingest_reading.py --title "..." --own --text "..." # 読後メモ
python scripts/ingest_reading.py --audit                       # 偏食監査
```

- **この CLI は Web を取得しない。** 取得は Claude（WebFetch）が行い、本文を stdin で渡す。
  取り込み経路に Bash とネットワークを同時に持たせないため（仕様 6-2）
- provenance は**ドメインで機械判定**する。本文の自己申告を採用しない。
  不明は最も深い側（個人発信・深度2）に倒す
- 安全走査は**本文抽出より前**（抽出処理自体が攻撃対象になり得る）
- 検出しても取り込みは止めない。旗を立てて人間に提示する

### 絶対に守ること

🔴 **`ingested_at`（知った時刻）は遡って記録できない。**
同一内容を再取り込みしても**上書きしない**。初回に触れた時刻こそが記録すべき値である。
既知時刻の上書きは、この設計における最も重大なデータ破壊。

🔴 **`raw/` は追記のみ。** Claude は編集も削除もできない
（`.claude/settings.json` の deny + `guard_protected.py` の二重防御）。

## 偏食監査（V3）

5指標 + 情報遅延。すべて frontmatter だけで計算でき、**追加のデータ取得を要さない**。

| 指標 | 最小サンプル |
|---|---|
| 保有偏重率 | 20件 |
| 論調非対称 | 銘柄あたり5件 |
| 情報源HHI | 30件 |
| 死蔵アイデア | 各群10件 |
| 着想→執行の遅延 | 8件 |

- **未達の指標は値を出さない。**「蓄積中（現在N件 / 必要M件）」だけ表示する
- 情報源HHI は `portfolio.concentration.compute_hhi` を共用（新規実装しない）
- **最も重要な出力は比率ではなく「批判ゼロの保有」の列挙**。
  ただし**その銘柄について1件も読んでいない場合は「批判ゼロ」ではなく「未測定」**
- 禁止表現: 「〜すべきです」「〜できていません」「偏っています」、目標値の提示

> 偏りは人間の標準であり、異常ではない。この節は矯正のためではなく、
> **自分の形を知るため**にある。

## 概念層（V4）

概念は3条件を**すべて**満たす: ①銘柄を売っても価値が残る ②複数に適用できる ③反証できる。

- 🔴 **反証事例が空の概念は登録できない。** 反証事例を書けない概念は
  反証不能な信念であり、概念として制約に使ってはならない。
  **これが概念層が教条の倉庫になることを防ぐ唯一の装置**
- confidence: 仮説 → 検証済 → 疑わしい。**廃止は自動化しない**
  （統計が悪いだけで知識を捨てるのは早計。サンプルが小さい）
- 制約に使えるのは `検証済` のみ。かつ**根拠が単一の取り込みだけの概念は保留**
  （外部から注入された知識をそのまま制約にしない = 緩慢な汚染への構造的防御）

## 系譜の根（V5）

| 状態 | 意味 |
|---|---|
| `no_source` | 根拠として登録された raw が0件。系譜を遡れない |
| `no_primary` | 一次資料（深度0）による裏取りが無い |
| `personal_only` | 個人発信（深度2）のみに依拠 |

**これは信頼度ではなく独立性の問題である。** 優れた個人発信は劣った業者資料より有用。

前提空間HHI は Concept の `is_assumption: true` として実装（第1弾との二重実装を回避）。
**取れないときに「前提が分散している」と絶対に書かない。**

## 週次レポート統合（V6）

- 節1: 保有の記述状態（4分類）
- 節2: テーゼの根拠系譜 + 概念の健全性 + 前提空間HHI
- 節7: 偏食監査
- **節8: 今週の取り込み** — 🔴 **0件でも必ず1行出す。折り畳んではならない。**
  取り込みが止まっていることは、この層における最も重要な故障だから
- 節9: 前提と限界

**打ち切り週（価格が取れない週）でも節8と偏食監査は出力する。**
「市場データが無いので分析しない」は「人間が何を読んだかも報告しない」を意味しない。

## 続かなくなる兆候

| 兆候 | 対策 |
|---|---|
| 取り込みが2週連続で0件 | 動線が重い。手順を1アクションに短縮できないか |
| `自分の考え` が0% | 読むだけで考えていない。読後メモの提案を強める |
| 概念が3ヶ月増えない | 粒度が高すぎる |
| thesis が3ヶ月増えない | ブートストラップ動線が機能していない |
| 偏食監査を読まなくなる | トーンが説教的。禁止表現を再点検 |

**1件の取り込みに3分かかるなら続かない。30秒で終わるなら続く。**
重ければ機能を足すのではなく**手順を削る**。
