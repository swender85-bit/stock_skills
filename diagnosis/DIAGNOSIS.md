## 1. 確定所見（8件）

### H1. 8/8 の全滅は「価格が取れない」ではなく起床レースだった

`output/weekly_deep.log` に `$2737.T … $QCOM … $JPY=X: possibly delisted` が
**為替を含む全銘柄**について並ぶ。特定銘柄の問題ではない。

`output/briefing/PF_20260808.json` の `meta.timings_sec` が決定的で、
`prices_and_holdings: 17.4`（全滅）に対し `narrative: 135.9`（成功）。
つまり**起動直後は繋がっておらず、後から繋がった**。WakeToRun でスリープから
起こされた直後に Wi-Fi が未接続だったことによる競合。

この事実は `src/data/yahoo_client/_net.py` の docstring に既に記録があり、
`wait_for_network()`（:76）/ `with_retry()`（:146）として**修正済み**。

- 証拠状態: **事実**
- 現況: 対処済み。ただし土曜の無人実行で効いたことはまだ一度も確認されていない（H8 参照）

### H2. 「総資産 ¥1,386,358」は実測ではなく「価格が取れた分だけの合計」

`src/core/portfolio/weekly.py:300`:

```python
invested = sum(a["value_jpy"] for a in analyses if a["value_jpy"] is not None)
```

価格が取れなかった9件が**黙って分母から消え**、`total = invested + cash_jpy` が
そのまま `total_jpy`（:378）としてヘッダに「総資産」と注記なしで表示された。
実際の規模は約 ¥22M（8/9 の出力）であり、**約94%の過少表示**。

数字が欠けたのではなく、**欠けた数字が正しい全体値の顔をして出た**。これが本件で最も危険な症状。

- 証拠状態: **事実**

### H3. 「評価損益 +2.1%」は分子と分母が別集合

`src/core/research/briefing_pack.py:905-913`（`_portfolio_summary`）:

```python
total_pl   = sum(a["pl_jpy"]   for a in analyses if a.get("pl_jpy")   is not None)
total_cost = sum(a["cost_jpy"] for a in analyses if a.get("cost_jpy") is not None)
... "pl_pct": (total_pl / total_cost * 100.0) if total_cost else None
```

分子 `total_pl` は**価格が取れた銘柄のみ**（8/8 は1件）。
分母 `total_cost` は取得単価から計算できるため**全10銘柄**。混合分母である。

H2 と違い、これはカバレッジ100%でないかぎり常に発生する。
**カバレッジ70〜99%の平常週でも今この瞬間に生きているバグ。**

- 証拠状態: **事実**

### H4. レポートは自分自身の欠落を黙った

`scripts/weekly_deep_driver.py:810`（`assemble`）:

```python
if s.get("status") != "done" or not s.get("file"):
    continue
```

失敗した3節（監査・限界・判定）は本文から**無言で削除**され、目次にも痕跡が残らない。

「取得できなかったものを『無かった』と書くな」を全節に課しているシステムが、
**自分自身の3節の欠落についてだけはそれを守らなかった。**

- 証拠状態: **事実**

### H5. 新設した品質ゲートに穴がある

`scripts/weekly_deep_driver.py:966` 付近。カバレッジ不足のパックで
`EXIT_INTERRUPTED` を返す新ゲートは、**`save_state` の前に return する**。

一方 `--resume-only` の再開タスクは、state が無ければ何もせず終了する（:945）。
よって土曜にこのゲートが発動すると、**その週はレポートが出ないまま、誰も気づかない。**
コード内コメントの「次の起動（最大3時間後）で取り直します」は事実に反する。

- 証拠状態: **事実**
- 注記: これは今回の改良で**新しく作り込んだ**穴である

### H6. 再試行の予算が「回数」であって「時刻」ではない

`--max-attempts` 既定2（`weekly_deep_driver.py:888`）。
8/8 は 12:10 に解除される使用量上限に対し、07:12 と 09:12 の2回で予算を使い切り、
**解除の3時間前に 15/18 節の状態で出荷**された。

取得層では「待てば直る失敗」と「待っても直らない失敗」を区別する実装を入れた
（`_net.py:126`）のに、**執筆層には同じ区別が無い**。

- 証拠状態: **事実**

### H7. 照合は構造上ほぼ常に循環する

`src/core/portfolio/reconciliation.py:388`:

```python
independent = [s for s in available if not (s.get("detail") or {}).get("circular")]
```

`independent` の定義は「模型の生成元でない残高ソース」。しかし楽天CSVは模型の生成元であり、
moomoo は残高ソースから除外済み（CLAUDE.md の方針）。**独立集合は設計上ほぼ空**である。

無人実行では証券会社にログインできない以上、脱出経路が無い。
「照合できていない」ことを正しく報告してはいるが、**永久に改善しない報告**になっている。

- 証拠状態: **事実**（構造の指摘。「どう直すべきか」は本書の範囲外）

### H8. 最新の出力構造は、無人パイプラインの産物ではない

`output/週次PF分析_20260809_v3.md`（カバレッジ100%・一次観測18件）の節構成は
`build_sections()` の固定骨格と一致せず、`output/weekly_deep.log` に生成記録も無い。
**対話セッションで手作りされたもの**である。

つまり「修正が効いた成果物」と「土曜に自動で出る成果物」は別物であり、
後者は 8/15 までまだ一度も検証されていない。

さらに v3 には**事前決定（土曜の唯一の行動）の節が無く**、代わりに
「私の見立て: 温存」という推奨が入っている。これは設計書の第0原則に反する。

- 証拠状態: **事実**

## 2. 所見の依存関係

```
H2 総資産の過少表示 ─┐
H3 混合分母        ─┼─→ 「取得の結果を『値 or None』で表す設計」に従属
H4 節の無言欠落     ─┤
H5 ゲートの穴       ─┘

H1 起床レース   ── 独立（対処済み）
H6 再試行予算   ── 独立
H7 照合の循環   ── 独立（構造的）
H8 未検証の本番 ── 独立（検証の欠如であって欠陥ではない）
```

最上流の候補は Phase A-3 で確定させる。本書は候補を1つ挙げるにとどめる:

> **観測の試行が第一級のデータになっていない。**
> 取得の結果を「値 or None」で表しているため、
> 「取得できなかった」と「取得できて値が無かった」と「そもそも観測しなかった」が
> 同じ `None` に潰れる。失敗は情報ではなく**穴**になり、穴のまま集計に入る。
