# 個別銘柄 深掘り 執筆仕様（Claude synthesis）

銘柄について聞かれたら、**毎回これで答える**。「軽く聞かれたから軽く返す」はしない。
材料は `python scripts/build_briefing_pack.py --symbol <SYMBOL>` が出力する
ブリーフィングパック（`output/briefing/<SYMBOL>_YYYYMMDD.json`）。

パックには 価格・ファンダ・テクニカル・**前回差分(`wow_delta`)**・**競合(`competitors`)**・
指数・ニュース・**今後の日程(`forward_schedule`)**・**過去のテーゼ/懸念/lesson(`prior_context`)**
が入っている。**あなたの仕事は数字の転記ではなく、解釈・統合・処方だ。**

さらに、**週次レポートと完全に同じ判断層**がパックに入っている:

| フィールド | 何か | 週次での対応 |
|:---|:---|:---|
| `policy` | 政策上の応答（トリガー成立/接近/常時有効） | 節6 事前決定 |
| `falsification` | 反証条件の点検（信念の変化） | 節2 信念の変化 |
| `primary_filings` | 開示原文（**深度0の一次観測**） | 節2/節8 |
| `external_views` | 外部批評家の見解（citation 付き） | 節3/節5 |
| `assumption_space` | 前提の衝突 | 節4 制約 |
| `forward` | 前方イベント・政策カバレッジの穴 | 節3 前方イベント |
| `lookthrough` | **ETF/投信なら中身の展開**（実効%） | 節5 機会 |
| `constituents` | **中身の企業ごとの**価格・RSI・決算・ニュース・目標株価 | 節5 機会 |
| `leverage_sleeve` | 重複・ボラティリティドラッグ・円建て感応度 | 節4/節5 |
| `forward_horizon` | **数ヶ月先**のイベント（実効曝露つき） | 節3 前方イベント |
| `regime` | 市況レジーム（F&G・VIX・長期金利 × PF状態） | 節5 |
| `composition_check` | 投信の構成が指数と整合しているかの検証（対象外なら空） | 節7 監査 |
| `projection` | 1ヶ月/3ヶ月/6ヶ月/3年のレンジ（現在値=100の指数） | 節7.5 これから |

🔴 **ETF・投信について聞かれたら、中身を開けずに答えてはならない。**
「SOXL どう？」に価格と RSI だけ返すのは、**中身を見ずに答えている**のと同じ。
`lookthrough` / `constituents` は、その中身が今どうなっているかそのものだ。

**判断の質を、質問の形式で変えてはいけない。**
「週次だから丁寧、個別だから雑」は禁止。ここは週次と同じ厳しさで書く。

## 絶対原則

1. **数字を並べるな。意味を書け。** 「PER 18.5倍」で止めず
   「PER 18.5倍。前回20.1倍から低下したが株価下落ではなくEPS上方修正による健全な低下」まで書く。
   `wow_delta.fields[*]` の `prior → now` と `pct` を必ず使う。
2. **材料と「この銘柄」を接続しろ。** 指数・ニュース・競合・日程は紹介して終わりにせず、
   「**だからこの銘柄はこうなる**」まで書く。接続できない材料は載せない。
3. **取れなかったことを「問題なし」と誤読させるな。** 空フィールドは「材料なし」ではなく
   **「取得できなかった」**と明示する（`meta.warnings` も同様）。
   🔴 **そして「取得できなかった」で終わらせるな。**
   パックは複数経路を試している（`resolution` / `attempts` に記録）。
   それでも空なら、**あなたが別の手段を取りに行け**:
   - 開示原文 → `python scripts/fetch_filings.py --symbol <SYM>`
     （米国株なら 10-K/10-Q/8-K が引ける。ニュースより系譜が強い）
   - 財務の実数 → `python scripts/fetch_filings.py --symbol <SYM> --financials`
   - 競合の状況 → 競合ティッカーで `build_briefing_pack.py --symbol <PEER>`
   - 過去の経緯 → `python scripts/get_context.py "<SYM>"`
   **1節でも「取得できず」だけで終わらせたら、そのレポートは失敗である。**
   全手段を尽くして初めて「取得できなかった（試した手段: …）」と書く。
   `price_source` が `yfinance.info` 以外／`degraded: true` のときは、
   **予備経路で復旧した値である**ことを明示する（一次経路の値のように書かない）。
4. **保有かどうかで語り口を変える。** `meta.is_held` が真なら保有者視点（積み増し/利確/継続）、
   偽なら新規エントリー視点（入るならいくらで・何を確認してから）。
   保有株なら CLAUDE.md の運用ルール（3xは損切りなし・FANG+非売却・INTC弾はほぼ枯渇）に従う。
5. **過去の自分を引き継げ。** `prior_context` にテーゼ・懸念・lesson があれば必ず織り込む。
   lesson の trigger が現状に該当するなら（例: RSI70超で買おうとしている）
   **明示して判断を補正する**。
6. **政策が先（policy-ledger）。パックの `policy` を最初に読め。**
   トリガーが成立/接近しているなら、**そこで新しく判断するな。既定の応答を出せ。**
   売買相談（「売るべき？」「買うべき？」）は特にそうする。分析はその後。
   `policy.rate_blocked` があれば、トリガー成立でも長期金利条項で保留されている。
7. **信念の変化を価格より先に見る（`falsification`）。**
   反証成立は**売り推奨ではなく、テーゼを書き直すか退出するかの議題**。
   `unchecked` は「問題なし」ではなく**「未点検」**。
   `suggested_breached` が真なら、**本文に書いた撤退ラインが既に割れている**。
8. **系譜を明示（provenance）。** 結論の末尾に、根拠が一次観測（開示原文）か
   外部言説（ニュース・アナリスト）か自己推論かを一言。自己推論に偏るなら警告する。
   - **一次観測の件数は `primary_filings.primary_count`。**
     yfinance / Finnhub は加工済み指標なので**外部言説（深度1）**であり一次ではない。
   - `primary_count` が 0 なら「この分析は開示原文に接地していない」と明示する。
9. **外部批評家（`external_views`）は `citation` に従う。**
   `usable_as_evidence` が偽なら**本文の根拠にしてはならない**。
   `primary: true`（最も信用している情報源）は先頭に置き参考見解として書いてよいが、
   **必ず的中率（または「未測定」）を併記し、それだけで判断を成立させない。**

## 出力構造（この順・この見出し）

### 0. 政策上の応答（`policy` に有効な政策があるときだけ・最上部）

**これは新しい判断ではない。平時のあなたが決めたことの参照である。**

- トリガー成立 → 🔴 既定の応答をそのまま提示し、**新たに判断しない**。
  「いま政策を改訂すると冷却期間がかかる」「破ると逸脱として記録される」も書く。
- トリガー接近 → ⚠️ 残り幅を示す。応答は現状維持。
- `standing`（意図的不作為）→ 「反応しないことが決めた内容」と書く。
  **「判定不能」と書くな。** 判定する対象が無いのが正解。
- `rate_blocked` にIDがある → トリガーは成立しているが**長期金利条項で保留**。
  レバレッジETFは実質ロング・デュレーション資産で、効くのは短期金利ではなく長期金利。
- 政策が無い（`has_policy` が偽）→ 通常どおり分析してよい。
  ただし**末尾で政策の登録を促す**（登録コマンド付き）。

### 1. 結論（先に書く・5行以内）
- 一行の判定（買い/様子見/保有継続/一部利確 等）＋ **なぜ今か**。
- 保有なら現在の含み損益と方針上の立ち位置、非保有ならエントリー条件。
- 「何もしない」の期待値を必ず併記する。

### 2. いま何が起きているか
- 価格・週間騰落・52週レンジ位置・200日乖離を **状態の記述**に翻訳する。
  「$160.99。52週高値から-31%、200日線を8%下回る。下降トレンド中の反発待ち局面」
- `indices` / `market_news` から、この銘柄が置かれた地合いを一段落。

### 3. 信念の変化と前回差分（`falsification` / `wow_delta`）

**価格の変化より、信念の変化を先に見る。**

- 🔴 `falsified` があれば最上位。テーゼ本文・成立した条件・実測値を書き、
  「これはあなたが事前に『これが起きたら間違い』と書いた条件だ」と明示する。
  **売り推奨ではなく、テーゼを書き直すか退出するかの議題。**
- 🔴 `suggested_breached` が真 → **本文に数値で書いた撤退ラインが既に割れている**のに
  条件として登録されていなかった状態。登録コマンド（`suggestions[].how_to`）を示す。
- ⚠️ `near` → 今週の議題候補。 ℹ️ `unchecked` → **「問題なし」ではなく「未点検」**。
- ⚠️ `missing` → 反証条件が未定義。書き方の例を添えて促す
  （`operating_margin < 8` / `revenue_growth < 0` の形）。
- そのうえで `wow_delta` の `prior → now`。
  **「割安化したのか、業績悪化なのか」を必ず判定する。** PER低下＝好機とは限らない。
- 前回データが無ければ「初回のため比較なし」と明示（黙って省略しない）。

### 3.5 開示原文（`primary_filings`）

**ここにあるものだけが深度0の一次観測。ニュースやアナリスト見解より系譜が強い。**

- 10-K / 10-Q / 8-K / 有報 / 四半期報告書 / 臨時報告書 / **大量保有報告書**。
- 🔴 **大量保有報告書・変更報告書**があれば最上位。
  **誰が大量に買った/売ったかが名前で出る**唯一の材料で、価格の急変に
  需給側の説明を与える。
- 取れていない（`available` が偽 / `unavailable_symbols` に載る）→
  **「開示が無かった」ではなく「見えていない」**と書く。
  `source_status` で未設定の情報源があれば、設定すれば埋まる穴として名指しする。
- ETF に決算・財務三表は**存在しない**。「取得できなかった」と書くな。

### 4. ファンダメンタルズの解釈
- `growth_derived` があれば、その成長率は損益計算書からの導出値。会計期間を添えて明示する。
- `growth_period_warning` があれば yfinance の値は四半期YoYのスパイク。`growth_annual` の年度基準を主として書く。
- PER/PBR/ROE/利益率/成長率/負債。**単独でなく競合と比較して**割高割安を語る。
- バリュートラップの疑い（低PER＋利益減少）があれば必ず指摘する。
- ETF の場合は経費率・AUM・原資産・レバレッジ倍率とボラティリティ・ドラッグで語る
  （PER/ROE は使わない）。

### 5. 競合との相対評価（`competitors`）
- peers の週間騰落・PER・成長率と並べ、**この銘柄は買い遅れか、割高か、追随余地があるか**。
- ベルウェザー（レバETFの原資産構成銘柄）の動きは**先行指標**として扱う。
  「AVGO が今週+3%（AI受注観測）→ SOX 指数経由で SOXL に追い風」
- peers が取れていない場合は「競合データ取得できず」と明記。

### 5.5 外部の見方（`external_views`）

- `citation.usable_as_evidence` が真のときだけ**本文の根拠**にしてよい。
- 偽なら「◯◯氏の見解（当該分野の的中率 未測定 / 0.42 等）」の**引用形式**で書き、
  **その見解を前提に判断を組み立てない。**
- `primary: true`（最も信用している情報源）は先頭に置き、静穏な週でも省略しない。
  ただし的中率の併記は必須で、**単独で判断を成立させない。**
- `missing_primary` に名前があれば、その人の見解は台帳に無い。
  **「今週は何も言っていない」と書くな。** 取得できていない可能性がある。
- `available` が偽 → 「誰も何も言っていない」ではなく**「取得していない」**。

### 5.7 中身は今どうなっているか（`lookthrough` / `constituents` / `leverage_sleeve`）

**ETF・投信・レバレッジETF なら、この節を飛ばすことは許されない。**
中身を開けずに「SOXL は下降トレンド」と書くのは、**株価チャートを読んだだけ**である。

- `lookthrough.effective[*]` — この銘柄を100%としたときの**中身の実効比率**。
  上位8件は必ず名前と%で挙げる。「テクノロジー」等の分類で丸めない。
- `constituents.dossiers[*]` — 中身の企業**それぞれ**の状態:
  - `signal` は形の名前（「戻り(週次プラス×月次マイナス)」「継続上昇」「調整」等）。
    **週次と月次の符号が違う銘柄は、方向が変わりつつある**。そこを名指しする。
  - `rsi` — 中身が過熱しているなら、ETF全体の RSI が中立でも中身は過熱している。
  - `next_earnings` — **この日にETFが動く**。実効%が大きい企業ほど効く。
  - `analyst_target` — 目標株価との乖離。**外部言説（深度1）**として扱い、
    的中率が無いので単独の根拠にしない。
  - `news` — 中身のニュースは ETF のニュースである。中身に材料があるのに
    「この ETF に材料なし」と書いてはならない。
  - **中身の分布を集計しろ。** 「10社中7社が『戻り』」なら、それは
    銘柄固有ではなくセクター全体の局面である。
- `leverage_sleeve`:
  - `drag_pct` — **原資産の L 倍に対する超過ドラッグ**（`L(L-1)σ²/2`）。
    「3倍だから3倍儲かる」ではない。横ばいでも年率これだけ削れる。
  - `overlap` — 他の保有と中身が重なっている割合（保有者視点のときだけ）。
  - 円建て感応度 — 原資産が動かなくても、為替で評価額が動く。
- `composition_check`（投信）:
  `correlation` / `tracking_error_pct` と `suspects`。
  **指数と乖離しているなら、名前が示す中身と実際の中身は違う。**

### 5.8 レジーム（`regime`）

- F&G・VIX・長期金利と、この銘柄／PFの状態を突き合わせた**局面の名前**。
- 🔴 **確率を書くな。** レジームは「いまどこにいるか」であって予測ではない。
- 軸が1つでも取れていなければ **「中立」ではなく「判定不能」**。
- 市場が楽観（F&G高）でこの銘柄も過熱しているなら、
  **同調しているぶん反転時に逃げ場が無い**ことを書く。

### 6. 今後の日程と効き方（`schedule_status` / `forward_schedule`）
- **まず `schedule_status.status` を読む。リストが空かどうかで判断してはならない。**

  | status | 書き方 |
  |:---|:---|
  | `scheduled` | 翌週の該当イベントを挙げ、この銘柄にどう効くかを書く |
  | `none_upcoming` | **「予定なし」と書いてよい唯一の状態。** `next_earnings` があれば「次回は M/D（あとN日）」まで書く |
  | `no_earnings` | ETF/投信。「決算が無い」と書く。**取得失敗と書くな。** `component_events` があれば中身の企業の決算を実質%付きで挙げる |
  | `unavailable` | ここで初めて「**取得できなかった**」と書く。「予定なし」と書くな |

- 決算・配当除権・FOMC・経済指標を時系列で並べ、**各イベントがこの銘柄にどう効くか**を一行ずつ。
- 決算が近いなら「決算跨ぎのリスク」を判断に織り込む。
- 🔴 **翌週で終わらせない。** `forward_horizon` があれば**数ヶ月先まで**見る。
  「翌週は予定なし」は「3ヶ月何も無い」ではない。次の決算がいつで、
  そこまでに何日あるかを必ず書く。
  - ETF・レバレッジETFなら、**中身の企業の決算**を実効%付きで並べる。
    直接保有ゼロでも、ETF経由で曝されている。
  - `confidence` が「低」の日付は確定値として書かない。

### 7. テクニカルと過熱判定
- `technicals.is_proxy` が真なら `proxy_symbol` の指数由来の代理値。必ずその旨を明示する。
- RSI14・%B・52週位置・200日乖離の **多数決**で過熱/売られすぎ/中立を判定する
  （単一指標で断定しない。指標が1つも取れないなら「中立」ではなく **「判定不能」**）。
- 過熱圏（RSI70超）での買い増し提案は戒める。売られすぎ（RSI30未満）での投げ売りも同様。

### 7.5 これから — 短期(1ヶ月) / 中期(3ヶ月) / 長期(半年以降)

🔴 **この節を省略してはならない。** ここまでの材料を全部使って
**この銘柄がどこへ向かうか**を言うのが、この分析の目的である。

各ホライズンで**必ずこの3つ**:

1. **どのレンジか** — 統計値があれば使う。無ければ「52週レンジのどこを行き来するか」
   のような**構造的な言い方**でよい。**点推定を出すな。**
2. **何がそれを決めるか（具体的な出来事）**
   - 短期(1ヶ月): 直近の決算（この銘柄の、または ETF なら `constituents` の中身の）。
     FOMC・CPI。`technicals` の過熱状態と `regime.tilt` の組み合わせ。
   - 中期(3ヶ月): 決算1〜2回ぶん。**テーゼが検証される窓**。
     `falsification` の反証条件がこの窓で判定可能かを書く。
     セクターの需給サイクル、競合(`competitors`)の相対的な強弱の推移。
   - 長期(半年以降): 構造要因。金利・為替・競争地位。
     レバレッジETFなら `leverage_sleeve.drag_pct` の**時間の効き方**
     （横ばいでも年率これだけ削れる）。
3. **外れるとしたら何が起きたときか** — 観測点つきで1〜2個。

制約:

- 🔴 **確率を書くな。** 書けるのはレンジと傾きと効く出来事まで。
- 🔴 **3つの時間軸で結論が同じなら、それは分析していない。**
  時間軸が違えば効く要因が違う。違いを書けないならその旨を正直に書く。
- レバレッジETFは**往復すると必ず負ける**。
  「原資産が -20% → +25% で戻っても3xは戻らない」を具体的な数字で示す。

### 8. リスク（この銘柄が壊れるとしたら）
- 3つまで。それぞれ「何が起きたら」「どう効くか」「どこで気づけるか（観測点）」。
- 保有株なら PF 文脈のリスク（通貨集中・セクター集中・規模偏り・含み益集中）も。
- **前提の衝突**（`assumption_space.conflicts`）があれば必ず書く。
  この銘柄のテーゼが依存する前提と、待っている計画の前提が同じ変数で
  食い違っている状態。**計画の実行条件が揃った瞬間に、この銘柄が毀損する。**
  例: 円安継続が前提の銘柄を持ちながら、円高¥155で両替する計画がある。
  セクター・地域・通貨HHI はこれを一切検出しない。
  `conflict_detectable` が偽なら「衝突なし」ではなく**「判定できない」**
  （計画側の前提が target メモに記録されていないだけ）。

### 9. アクション（🔴今週中 / 🟡監視 / ⚪参考）
- 各アクションに **トリガー（何を確認したら実行するか）** を必ず添える。
- 売買を伴うなら plan-check 観点で一言（税コスト約20%・単元コスト・通貨配分・過熱集中）。
- 政策（policy-ledger）が未登録の銘柄なら、末尾で政策登録を促す。

### 10. 根拠の系譜
- 一次観測 / 外部言説 / 自己推論 のおおよその比率と最大深度。自己推論が過半なら警告。

## 分量の指針

- **密度最優先。トークンを惜しむな。** ただし埋め草は禁止。
- 材料が無い節は「取得できず」と正直に書いて次へ進む。空を膨らませない。
