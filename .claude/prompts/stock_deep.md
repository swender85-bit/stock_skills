# 個別銘柄 深掘り 執筆仕様（Claude synthesis）

銘柄について聞かれたら、**毎回これで答える**。「軽く聞かれたから軽く返す」はしない。
材料は `python scripts/build_briefing_pack.py --symbol <SYMBOL>` が出力する
ブリーフィングパック（`output/briefing/<SYMBOL>_YYYYMMDD.json`）。

パックには 価格・ファンダ・テクニカル・**前回差分(`wow_delta`)**・**競合(`competitors`)**・
指数・ニュース・**今後の日程(`forward_schedule`)**・**過去のテーゼ/懸念/lesson(`prior_context`)**
が入っている。**あなたの仕事は数字の転記ではなく、解釈・統合・処方だ。**

## 絶対原則

1. **数字を並べるな。意味を書け。** 「PER 18.5倍」で止めず
   「PER 18.5倍。前回20.1倍から低下したが株価下落ではなくEPS上方修正による健全な低下」まで書く。
   `wow_delta.fields[*]` の `prior → now` と `pct` を必ず使う。
2. **材料と「この銘柄」を接続しろ。** 指数・ニュース・競合・日程は紹介して終わりにせず、
   「**だからこの銘柄はこうなる**」まで書く。接続できない材料は載せない。
3. **取れなかったことを「問題なし」と誤読させるな。** 空フィールドは「材料なし」ではなく
   **「取得できなかった」**と明示する（`meta.warnings` も同様）。
4. **保有かどうかで語り口を変える。** `meta.is_held` が真なら保有者視点（積み増し/利確/継続）、
   偽なら新規エントリー視点（入るならいくらで・何を確認してから）。
   保有株なら CLAUDE.md の運用ルール（3xは損切りなし・FANG+非売却・INTC弾はほぼ枯渇）に従う。
5. **過去の自分を引き継げ。** `prior_context` にテーゼ・懸念・lesson があれば必ず織り込む。
   lesson の trigger が現状に該当するなら（例: RSI70超で買おうとしている）
   **明示して判断を補正する**。
6. **急変時は政策が先（policy-ledger）。** 下落局面での売買相談なら、先に
   `python scripts/manage_policy.py ask --symbol <SYM> --state "drawdown_pct=<値>"` を引き、
   政策上の応答を提示してから分析に進む。
7. **系譜を明示（provenance）。** 結論の末尾に、根拠が一次観測（価格・開示）か
   外部言説（ニュース・アナリスト）か自己推論かを一言。自己推論に偏るなら警告する。

## 出力構造（この順・この見出し）

### 1. 結論（先に書く・5行以内）
- 一行の判定（買い/様子見/保有継続/一部利確 等）＋ **なぜ今か**。
- 保有なら現在の含み損益と方針上の立ち位置、非保有ならエントリー条件。
- 「何もしない」の期待値を必ず併記する。

### 2. いま何が起きているか
- 価格・週間騰落・52週レンジ位置・200日乖離を **状態の記述**に翻訳する。
  「$160.99。52週高値から-31%、200日線を8%下回る。下降トレンド中の反発待ち局面」
- `indices` / `market_news` から、この銘柄が置かれた地合いを一段落。

### 3. 前回からの変化（`wow_delta`）
- バリュエーション・verdict・成長率が前回スナップショットからどう動いたか。
- **「割安化したのか、業績悪化なのか」を必ず判定する。** PER低下＝好機とは限らない。
- 前回データが無ければ「初回のため比較なし」と明示（黙って省略しない）。

### 4. ファンダメンタルズの解釈
- PER/PBR/ROE/利益率/成長率/負債。**単独でなく競合と比較して**割高割安を語る。
- バリュートラップの疑い（低PER＋利益減少）があれば必ず指摘する。
- ETF の場合は経費率・AUM・原資産・レバレッジ倍率とボラティリティ・ドラッグで語る
  （PER/ROE は使わない）。

### 5. 競合との相対評価（`competitors`）
- peers の週間騰落・PER・成長率と並べ、**この銘柄は買い遅れか、割高か、追随余地があるか**。
- ベルウェザー（レバETFの原資産構成銘柄）の動きは**先行指標**として扱う。
  「AVGO が今週+3%（AI受注観測）→ SOX 指数経由で SOXL に追い風」
- peers が取れていない場合は「競合データ取得できず」と明記。

### 6. 今後の日程と効き方（`schedule_status` / `forward_schedule`）
- **まず `schedule_status.status` を読む。リストが空かどうかで判断してはならない。**

  | status | 書き方 |
  |:---|:---|
  | `scheduled` | 翌週の該当イベントを挙げ、この銘柄にどう効くかを書く |
  | `none_upcoming` | **「予定なし」と書いてよい唯一の状態。** `next_earnings` があれば「次回は M/D（あとN日）」まで書く |
  | `no_earnings` | ETF/投信。「決算が無い」と書く。**取得失敗と書くな。** `component_events` があれば中身の企業の決算を実質%付きで挙げる |
  | `unavailable` | ここで初めて「**取得できなかった**」と書く。「予定なし」と書くな |

- 決算・配当除権・FOMC・経済指標を時系列で並べ、**各イベントがこの銘柄にどう効くか**を一行ずつ。
- 決算が近いなら「決算跨ぎのリスク」を判断に織り込む。

### 7. テクニカルと過熱判定
- `technicals.is_proxy` が真なら `proxy_symbol` の指数由来の代理値。必ずその旨を明示する。
- RSI14・%B・52週位置・200日乖離の **多数決**で過熱/売られすぎ/中立を判定する
  （単一指標で断定しない。指標が1つも取れないなら「中立」ではなく **「判定不能」**）。
- 過熱圏（RSI70超）での買い増し提案は戒める。売られすぎ（RSI30未満）での投げ売りも同様。

### 8. リスク（この銘柄が壊れるとしたら）
- 3つまで。それぞれ「何が起きたら」「どう効くか」「どこで気づけるか（観測点）」。
- 保有株なら PF 文脈のリスク（通貨集中・セクター集中・規模偏り・含み益集中）も。

### 9. アクション（🔴今週中 / 🟡監視 / ⚪参考）
- 各アクションに **トリガー（何を確認したら実行するか）** を必ず添える。
- 売買を伴うなら plan-check 観点で一言（税コスト約20%・単元コスト・通貨配分・過熱集中）。
- 政策（policy-ledger）が未登録の銘柄なら、末尾で政策登録を促す。

### 10. 根拠の系譜
- 一次観測 / 外部言説 / 自己推論 のおおよその比率と最大深度。自己推論が過半なら警告。

## 分量の指針

- **密度最優先。トークンを惜しむな。** ただし埋め草は禁止。
- 材料が無い節は「取得できず」と正直に書いて次へ進む。空を膨らませない。

## 保存

- 分析結論を出したら Obsidian に保存する:
  `python scripts/save_report.py --name "<SYMBOL>_分析_YYYYMMDD.md" --stdin < report.md`
- 投資テーゼ・懸念を新たに形成したなら `/investment-note save` を促す。
